# Graphium Artifacts

Artifacts are **named values** that flow between steps in a `graph! { ... }` workflow.
They are the glue between nodes: nodes produce artifacts, and other nodes consume them.

This document focuses on the *artifact ownership model* used by the Graphium DSL and how that maps to the Rust code generated by `graph!`.

**See also**

- `index.md` (documentation map)
- `dsl.md` (DSL syntax and operators)
- `graphs.md` (how artifacts are propagated in generated code)
- `nodes.md` (node signatures vs artifact wiring)

## Prerequisites

The examples below use `use graphium::{graph, node};`, which requires enabling the `macros` feature:

```toml
[dependencies]
graphium = { version = "0.1", features = ["macros"] }
```

Alternatively, import macros directly with `use graphium_macro::{graph, node};`.

## What an artifact is (and isn’t)

- An artifact is **a slot identified by name** (e.g. `number`, `dataset`, `model`) in the graph’s dataflow.
- Artifacts are **not variables** you can use in normal Rust; they are DSL identifiers that the macro wires up.
- Artifacts are always **owned values internally** (Graphium requires `Clone + 'static`), even when you *use* them as borrowed (`&...`) inside the DSL.

Because artifacts must be cloneable, Graphium can:

- **Fan-out** one produced value to multiple immediate consumers by cloning it.
- **Persist** a value inside the graph so later nodes can borrow it.

## Syntax at a glance

In the DSL, each artifact occurrence is one of the following forms:

| Kind | Syntax | Meaning |
|---|---|---|
| Owned | `artifact` | Move an owned artifact into a node (or bind an owned output). |
| Borrowed | `&artifact`, `&mut artifact`, `&'a artifact`, `&'a mut artifact` | Borrow an artifact that has been persisted into the graph. |
| Taken | `*artifact`, `*mut artifact`, `*'a artifact`, `*'a mut artifact` | Move the value *out of* graph storage into a node (consumes it). |

Notes:

- The lifetime marker (like `'a`) is optional in artifact syntax. If you use it, declare it on the graph type (e.g. `MyGraph<'a>`).
- `*...` is only valid for **inputs** (you can’t “output” a taken artifact).

## Owned artifacts (move semantics)

By default, artifacts are **owned** values. Passing an owned artifact into a node input **moves** it, so it can’t be used again unless it is produced again later.

```rust
use graphium_macro::{graph, node};

node! {
    fn get_number() -> u32 {
        42
    }
}

node! {
    fn increment(number: u32) -> u32 {
        number + 1
    }
}

graph! {
    ExampleGraph -> (number: u32) {
        GetNumber() -> (number) >>
        Increment(number) -> (number)
    }
}
```

### Fan-out (automatic cloning)

If the same owned artifact is needed by multiple nodes within the same step, Graphium clones it (via `graphium::clone_artifact`) so each consumer receives its own owned value.

This is why artifacts must implement `Clone`.

## Borrowed artifacts (persisted in the graph)

Borrowing (`&...`) is only possible for artifacts that have been **persisted** into the graph.
You persist an artifact by listing it as a **borrowed output** of some node call:

- Persist as shared: `-> (&artifact)` or `-> (&'a artifact)`
- Persist as mutable: `-> (&mut artifact)` or `-> (&'a mut artifact)`

When an artifact is persisted, Graphium stores an **owned value** in graph-local storage and later nodes can borrow it with `&...`.

```rust
use graphium_macro::{graph, node};

node! {
    fn get_number() -> u32 { 42 }
}

node! {
    fn bump(number: &mut u32) { *number += 1; }
}

node! {
    fn read(number: &u32) -> u32 { *number }
}

graph! {
    BorrowedGraph<'a> -> (result: u32) {
        GetNumber() -> (&'a mut number) >>
        Bump(&'a mut number) >>
        Read(&'a number) -> (result)
    }
}
```

### Persisting without returning anything (“store” pattern)

A node does **not** need to return the persisted value.
If a borrowed output name matches one of the node’s inputs, Graphium clones that input into graph storage.

This is useful for nodes that perform side effects (logging, metrics, I/O) and you still want to keep the value alive for later steps.

```rust
use graphium_macro::{graph, node};

node! { fn get_number() -> u32 { 42 } }
node! { fn store_number(_number: u32) { /* side effect */ } }
node! { fn read(number: &u32) -> u32 { *number } }

graph! {
    StorePattern<'a> -> (out: u32) {
        GetNumber() -> (number) >>
        StoreNumber(number) -> (&'a number) >>
        Read(&'a number) -> (out)
    }
}
```

## Taking from graph storage (`*`)

`*...` moves the owned value out of graph storage into a node input, consuming it.
After a take, the artifact is no longer available to be borrowed.

```rust
use graphium_macro::{graph, node};

node! { fn get_number() -> u32 { 42 } }
node! { fn take(number: u32) -> u32 { number } }

graph! {
    TakeGraph<'a> -> (out: u32) {
        GetNumber() -> (&'a number) >>
        Take(*'a number) -> (out)
    }
}
```

## Mutability (`&mut` and `*mut`)

Use `&mut` to mutate a persisted artifact in place, and `*mut` to take it out afterwards:

```rust
use graphium_macro::{graph, node};

node! { fn get_number() -> u32 { 42 } }
node! { fn bump(number: &mut u32) { *number += 1; } }
node! { fn take(number: u32) -> u32 { number } }

graph! {
    MutBorrowGraph<'a> -> (out: u32) {
        GetNumber() -> (&'a mut number) >>
        Bump(&'a mut number) >>
        Take(*'a mut number) -> (out)
    }
}
```

## Node signatures and artifact types

The DSL must match the Rust signatures generated by `node!`:

- If a node input is `T`, pass an **owned** artifact: `Node(value)`.
- If a node input is `&T`, pass a **borrowed** artifact: `Node(&value)` / `Node(&'a value)`.
- If a node input is `&mut T`, pass a **mutable borrowed** artifact: `Node(&mut value)` / `Node(&'a mut value)`.

Node return types must be **owned** (no references). If you want downstream nodes to borrow something, persist it via `-> (&artifact)` so the graph can store an owned copy.

## Context vs artifacts

Graphs can be parameterized with a context type (e.g. `MyGraph<Context>` or `MyGraph<'a, Context>`).
Nodes that accept `&Context` / `&mut Context` (named `ctx` or `_ctx`) automatically receive the graph context.

Context is separate from artifacts:

- Context is explicit shared state passed through the `ctx` parameter.
- Artifacts are the dataflow values wired by the DSL.

## Practical guidelines

- Use **owned artifacts** for straightforward “pipeline” dataflow.
- Use **borrowed outputs** to persist a value when multiple downstream nodes need read/write access.
- Use **taken inputs** (`*...`) when a value must leave graph storage and be consumed.
- Prefer keeping artifact names stable and meaningful; they are part of the graph’s “public surface” (especially when exporting/visualizing).
